## 2. Таблицы (GFM и `:::table`)

### 2.1 Распознавание (сегментер в `RichText`, до markdown)
- Вход: тело блока (строка `body`). Выход: последовательность сегментов `{kind:'text'|'table', ...}`.
- Таблица = строка-шапка с `|` + строка-разделитель `^\s*\|?\s*:?-{3,}:?\s*(\|\s*:?-{3,}:?\s*)*\|?\s*$`, число колонок совпадает с шапкой, затем подряд идущие строки с `|`, до пустой строки или строки без `|`.
- Внутри `$$…$$` и fence ``` ``` ``` таблиц нет: сегментер пропускает эти участки.
- Экранирование `\|` внутри ячейки = литерал `|`.
- Выравнивание из разделителя: `:---` слева (по умолчанию), `:---:` по центру, `---:` справа; применяется к шапке и ячейкам колонки.
- Таблица без шапки: блок из ≥2 строк с `|`, без строки-разделителя, в `:::table` и `:::compare-table` → все строки тела, шапки нет, жирности нет. В обычном тексте без разделителя — не таблица (остаётся текстом).
- Пустые ячейки — пустой прямоугольник с сохранённой сеткой. Строка короче шапки — дополнить пустыми. Длиннее — лишние ячейки отбросить, **parser пишет warning**, текст не теряется в тихую.
- Сломанная таблица (шапка и разделитель с разным числом колонок, разделитель не похож на разделитель): **не таблица**, строки выводятся как обычный абзац с сохранением `|`, warning. Текст не съедается ни в каком случае.

### 2.2 Ячейка
- Инлайн-разметка: `**жирный**`, `*курсив*`/`_курсив_`, `` `код` `` (фон rt.fill, mono 0.88F), `$формула$` — mono 0.95 без MathBlock (дефолт фазы 1). Остальное — литерал.
- Ссылки в ячейках: текст с подчёркиванием, без действия (фаза 1).
- Перенос по словам, `numberOfLines` не задаётся: ячейка растёт по высоте.
- Выделение: каждая ячейка — отдельный `selectable` Text (см. §3).

### 2.3 Геометрия и ширина колонок
- Внешняя рамка: hairline 1px `rt.rule` с альфой 0.25 (через `rt.rule` + opacity, не новый hex), радиус 14, внутри `overflow:hidden`.
- Линии между строками и колонками: hairline 1px того же цвета, толщина `StyleSheet.hairlineWidth` допустима.
- Шапка: фон `rt.fill`, жирный, без зебры.
- Ширина колонки: `w_i = clamp(maxLen_i · 0.55 · cellFont + 2·pad, minW, maxW)`, `pad = 8`, `minW = 96`, `maxW = 240`, где `maxLen_i` — длина самого длинного слова колонки (не всей строки): так длинные слова не раздувают колонку без нужды, а длинные фразы переносятся.
- Если `Σw_i ≤ доступная ширина` (экран минус 2·16) — колонки растягиваются пропорционально `w_i`, скролла нет.
- Если `Σw_i > доступная` — горизонтальный `ScrollView` (`horizontal`, `showsHorizontalScrollIndicator={false}`), ширины не сжимаются ниже `minW`.
- Первый столбец не закреплять (по решению).
- Вложенный скролл: таблица внутри документа — горизонтальный, вертикальный скролл остаётся у документа.

### 2.4 Поведение по числу колонок (ширина 360dp, доступно ≈328)
| Колонок | Поведение |
|---|---|
| 1 | одна колонка на всю ширину, шапка остаётся жирной строкой |
| 2 | пропорционально, без скролла |
| 3 | без скролла, если текст короче ~24 символов на ячейку; иначе скролл |
| 5 | скролл (Σ ≈ 5·96 минимум) |
| 8 | скролл, ширина ячейки = minW; контент переносится по словам |

### 2.5 Граничные случаи
- Длинное слово (>колонки): перенос по символам не гарантирован RN — допустим горизонтальный скролл таблицы. Проверяется на телефоне (A7).
- Пустая таблица (шапка + разделитель, 0 строк): рисуется только шапка, warning «таблица без строк».
- Таблица, вся из пустых ячеек: рисуется сетка (не выкидываем — значит автор так задумал), warning.
- Таблица 1×1: рисуется как ячейка в рамке.
- Масштаб шрифта 14→22: ширина считается от F, высота растёт, ничего не обрезается.
- Тема: все цвета из `rt`; в тёмных темах hairline тот же токен.

### 2.6 Парсинг `:::table` и `:::compare-table`
- `:::table` — алиас `:::compare-table` в TS-парсере (`smdParser.ts:409`), Python-эталоне (`parser.py:932`) и SPEC.md — в одной поставке.
- Идентичный результат: один и тот же тип `compare-table` в `SmdBlock`, поля `head`, `rows`, `cols` одинаковы. Одинаковые поля — в TS и Python.
- Атрибут `cols` читать в TS так же, как в Python (диапазон `N` или `N..M`), warning при несовпадении. Это закрывает расхождение из §0.
- Приоритет: если имя блока `table` и `compare-table` — оба указывают на один парсер. Если в одном документе встречаются оба — допустимо, без предупреждения.
- Если тело без таблицы: `theory` с warning (текущее поведение сохраняем, но warning пишем в обоих парсерах с одним текстом).

## 3. Выделение текста (учебный документ)
- Что `selectable`: абзац (`paragraph`), заголовки h1–h6, элемент списка (`list_item`), ячейка таблицы, тело `theory`/`def`/`theorem`/`proof`/`summary`/`callout`/`formula`, раскрытое тело `spoiler`/`solution`. Реализация — переопределением `rules` у `Markdown` и в `RichText` для текстовых сегментов. На каждом inline-узле `selectable` не ставим: жирный и курсив внутри абзаца выделяются вместе с ним.
- Что НЕ `selectable`: заголовки и подписи интерактивов (title спойлера, question quiz, варианты ответов, фронт/бэк карточки, label блоков, кнопки). Причина: длинный тап на них должен давать действие, а не выделение.
- Долгое нажатие на абзац → системное выделение слова, маркеры расширения, меню «Копировать». Копируется отображённый текст (без `**`).
- Тап по документу (короткий) — продолжает скрывать интерфейс (как сейчас). Тап по интерактивам (quiz, cloze, spoiler, card, checklist) — работает свой обработчик, интерфейс не скрывается.
- Выделение не выходит за пределы одного абзаца/ячейки. Межблочное выделение — вне фазы 1 (см. Q1).
- Цвет подсветки — системный. Кастомизацию не делаем (RN `Text` её не даёт на Android без хака).
